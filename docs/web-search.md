# 联网补充（Tavily API）

输入框中的「联网补充」默认关闭。开启后每轮仍先查询本地商品：

1. 本地有符合预算、品类及硬约束的候选，且指定型号全部匹配：继续原有详情、价格、评价和确定性评分，不调用 Tavily。
2. 本地没有匹配候选，或对比中缺少任意一款指定型号：先查当前用户、查询及约束对应的网页缓存。其他型号的向量近邻不算目标型号已入库。
3. 缓存缺失或超过有效期：调用 Tavily basic 搜索，筛选有摘要、公开来源链接且相关分数不低于 0.35 的结果，最多保留 5 条。
4. 保存有效网页摘录，再交给 Agent 作带来源链接的补充建议。没有足够证据时明确说明，不能编造价格或硬约束满足情况。

## 本地配置

在项目根目录或 backend/.env 添加 `TAVILY_API_KEY`，仅填写到本地配置，不提交密钥。无需新增 Python 依赖，使用已有 httpx 调用 Tavily API。

```dotenv
TAVILY_API_KEY=
WEB_SEARCH_CACHE_HOURS=6
WEB_SEARCH_TIMEOUT_SECONDS=15
WEB_SEARCH_MAX_CALLS=2
```

首次更新后在 backend 执行：

```powershell
conda activate agent
python -m alembic upgrade head
```

重新启动后端即可读取配置。未配置密钥时本地推荐仍可用；只有需要联网补充时才提示配置缺失。

## 保存与更新

- `web_evidence` 保存标题、URL、摘要、内容哈希、来源类型、相关性、网页提供的发布时间和实际获取时间。
- 稳定 ID 由用户、URL 和内容哈希生成。同内容重复检索更新获取时间；网页摘要发生变化时保存新版本。
- `web_search_cache` 保存查询及预算/约束哈希、证据 ID 列表和过期时间。同一有效查询复用资料，避免再次消耗额度。
- 资料按用户隔离。推荐记录保存本轮证据快照，即使后续更新也可以追溯。
- 网页资料保存为独立证据，同时生成管理员待处理记录。搜索本身不覆盖 products/product_prices，也不写入 Chroma。管理员审核通过后才新增或补充正式商品并更新索引，详见 [商品更新审核](product-updates.md)。
- 网页候选以带来源的文字建议展示，不伪造本地商品卡片、商品 ID 或确定性分数。它们的准确性依赖网页证据，获取时间不等于价格或发布时间。
- 关闭后不加载联网工具、不查询网页证据缓存。此前联网模式生成的助手回答也不进入关闭模式的模型上下文，摘要仅使用本地回答及用户需求。
- 搜索超时、额度不足时显示原因；有旧缓存时显式标为过期资料。保存失败时本轮仍能引用新结果，但界面显示「未保存」。

缓存目前采用同一查询与约束的精确匹配，不是跨查询的网页向量检索。搜索结果仍须按来源、配置、地区和日期核验。

指定型号保存在会话的 `requested_models` 中，中文品牌和常见别名规范化后核对 MySQL 商品名称、型号与品牌。该路径不依赖向量 Top-K，避免只返回无关近邻或漏掉对比的另一款。普通品类推荐继续使用原有检索方式。每次工具查询都会重新判断本轮覆盖情况，之前命中的候选不会永久阻断新查询。

## 验证

`python -m pytest tests/test_web_search.py` 覆盖默认关闭、本地命中零网络请求、空库搜索、缓存复用及过期更新、来源去重、用户隔离、错误降级和上下文隔离。

调试完成后使用 Ctrl+C 关闭临时后端和前端进程。
