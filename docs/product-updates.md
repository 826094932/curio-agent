# 管理员审核商品更新

联网回答仍先检索本地。搜索保存网页证据后，额外生成 `product_updates` 待处理记录；此时不调用结构化模型，也不写正式商品。

## 操作

1. 管理员登录后进入「数据工作台 → 商品更新记录」。旧网页资料可点击「同步历史资料」。
2. 选择记录，核对或替换为具体品牌官网产品/参数页，点击「生成商品草稿」。这一步调用 Tavily Extract 和 DeepSeek，耗时与额度发生在管理操作中。Tavily 接口说明：[Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)。
3. 核对商品型号、配置、规格及逐字原文依据。必要时编辑草稿；编辑后重新校验，不接受没有依据的规格。
4. 点击「审核通过，加入商品库」。按品类、品牌、完整型号与配置规范化去重，新商品插入 `products`；已有商品默认只补空缺规格。冲突字段只有管理员逐项勾选才会替换。
5. 商品和审核变更先一起提交 MySQL，再更新 Chroma。失败显示「索引待重试」，重试只更新索引，不重复创建商品。

第三方资料保留为线索，生成正式商品草稿需要受支持品牌的 HTTPS 官网。包括 Apple、小米、Sony、Beats、Bose、华为、荣耀、三星、OPPO、vivo、联想、戴尔、华硕和惠普；识别逻辑见 `app/ingestion/sources.py`。

## 数据与恢复

- 公开线索按 URL + 内容哈希跨用户去重；队列不复制用户提问、账号、API 配置。原网页证据与查询缓存继续按用户隔离。
- 搜索内容变化产生新记录；相同内容不会重新打开已入库或已忽略的记录。
- 草稿留在审核表中。只有明确审批后才生成启用商品、参与本地检索；关闭联网也可以检索已经审批的正式商品。
- 不从网页摘要生成价格/库存快照。缺少价格的商品仍会被预算条件过滤，价格需要原有独立导入流程。
- 记录提取、审核、MySQL 前后值、替换字段、原文依据、索引结果及阶段耗时。网页抓取时间是获取时间，不代表厂家参数更新时间。
- 审核使用版本号和正式商品快照哈希；其他操作修改了商品时先刷新差异。当前遵循项目单后端实例约束，和导入/重建共用索引锁。
- 重启时将中断的提取标为「提取失败」供重试；已经提交商品的「索引待重试」保留。
- 更新队列保存失败不会撤销网页证据；可用「同步历史资料」补齐。

## 更新已有环境

在 `backend` 执行并重新启动后端：

```powershell
python -m alembic upgrade head
python -m scripts.sync_product_updates
```

同步历史仅新增待审核记录，不调用外部 API，不自动审批商品。新环境迁移会自动建表。
